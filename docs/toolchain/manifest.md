# Manifest (`Package.ll`) and lockfile

Every LLLang **package** is described by a **`Package.ll`** file at the package root — a declarative LLLang program in the same spirit as Swift’s `Package.swift`. Reproducible builds use **`Package.lock`**, generated by the package manager.

Monorepos that compose many packages use a root **`Solution.ll`** (see [Solutions](solutions.md)), analogous to a .NET `.sln`.

## Tools version

The first line pins the Package Description API:

```ll
// lang-tools-version: 0.1
```

Older toolchains refuse manifests that require a newer tools version.

## Shape overview

```ll
// lang-tools-version: 0.1
import Std.PackageDescription

let package = Package(
    name: "shop.checkout",
    defaultLocalization: "en",
    platforms: [
        .macOS("13.0"),
        .linux,
    ],
    products: [
        .executable(name: "checkout", targets: ["Checkout"]),
        .library(name: "CheckoutCore", targets: ["CheckoutCore"]),
    ],
    dependencies: [
        .package(id: "std.http", from: "0.5.0"),
        .package(id: "acme.payments", from: "1.2.0"),
        .package(path: "../LocalKit"),                 // path dep
        .package(url: "https://git.example/kit.git", from: "2.0.0"),
    ],
    targets: [
        .target(
            name: "CheckoutCore",
            dependencies: [
                .product(name: "Http", package: "std.http"),
                .product(name: "Payments", package: "acme.payments"),
            ],
            path: "Sources/CheckoutCore",
        ),
        .executableTarget(
            name: "Checkout",
            dependencies: ["CheckoutCore"],
            path: "Sources/Checkout",
        ),
        .testTarget(
            name: "CheckoutCoreTests",
            dependencies: ["CheckoutCore"],
            path: "Tests/CheckoutCoreTests",
        ),
    ],
    swiftSettings: [],   // reserved / ignored — LLLang uses `settings:`
    settings: [
        .define("FEATURE_X", .when(configuration: .debug)),
    ],
)
```

`Package.ll` is **evaluated by the toolchain** (not linked into your app). Only the `package` binding is read.

## `Package` fields

| Field | Type | Description |
|-------|------|-------------|
| `name` | `String` | Package id (reverse-DNS preferred, e.g. `acme.billing`) |
| `platforms` | `[Platform]` | Minimum OS / ABI floors |
| `products` | `[Product]` | What consumers and `lang run` see |
| `dependencies` | `[PackageDependency]` | Registry, URL, or path packages |
| `targets` | `[Target]` | Compile units (sources + deps) |
| `defaultLocalization` | `String?` | Optional locale for resources |
| `settings` | `[BuildSetting]` | Defines, unsafe flags, link libraries |

### Products

| Factory | Role |
|---------|------|
| `.executable(name:targets:)` | Runnable binary (`lang run --product Name`) |
| `.library(name:targets:type:)` | Publishable library → `.sbl` + `.bll` |
| `.plugin(...)` | Future build plugins |

Library `type`: `.automatic` (default), `.static`, `.dynamic`.

### Dependencies

| Factory | Role |
|---------|------|
| `.package(id:from:)` | Registry package, lower-bound inclusive |
| `.package(id:exact:)` | Pin exact version |
| `.package(id:range:)` | Semver range string (`"^1.2"`, `"~1.4"`) |
| `.package(url:from:)` | Git URL |
| `.package(path:)` | Local path (monorepo / vendoring) |

Dev-only dependencies attach on **test targets**, not via a separate TOML table:

```ll
.testTarget(
    name: "CoreTests",
    dependencies: [
        "Core",
        .product(name: "Snap", package: "test.snap"),
    ],
)
```

### Targets

| Factory | Role |
|---------|------|
| `.target(name:dependencies:path:exclude:resources:)` | Library / shared module |
| `.executableTarget(...)` | App / CLI entry (looks for `main` or top-level statements) |
| `.testTarget(...)` | `lang test` discovery |
| `.systemLibrary(...)` | Future C sysroot wrappers |
| `.binaryTarget(name:path:)` / `.binaryTarget(name:url:checksum:)` | Consume a prebuilt `.bll` |

Default source layout (SPM-like):

```text
Sources/<TargetName>/**/*.ll
Tests/<TargetName>/**/*.ll
```

Override with `path:`.

Target dependency items:

- `"SamePackageTarget"` — string shorthand
- `.target(name:)` — same package
- `.product(name:package:)` — product from a package dependency
- `.byName(name:)` — resolve product or target by name

### Settings

```ll
settings: [
    .define("DEBUG", .when(configuration: .debug)),
    .unsafeFlags(["-fno-omit-frame-pointer"], .when(configuration: .debug)),
    .linkedLibrary("m", .when(platforms: [.linux])),
]
```

## Minimal examples

### Console app

```ll
// lang-tools-version: 0.1
import Std.PackageDescription

let package = Package(
    name: "hello",
    products: [
        .executable(name: "hello", targets: ["Hello"]),
    ],
    targets: [
        .executableTarget(name: "Hello", path: "Sources/Hello"),
    ],
)
```

### Library

```ll
// lang-tools-version: 0.1
import Std.PackageDescription

let package = Package(
    name: "acme.math",
    products: [
        .library(name: "Math", targets: ["Math"]),
    ],
    targets: [
        .target(name: "Math", path: "Sources/Math"),
        .testTarget(name: "MathTests", dependencies: ["Math"], path: "Tests/MathTests"),
    ],
)
```

## `Package.lock`

Lockfile written by `lang add`, `restore`, and `update`. **Do not hand edit.** Format is TOON (compact, machine-oriented):

```toon
version: 1
packages[2]:
  - name: acme.payments
    version: 1.2.4
    sbl: blake3:abc123...
    source: https://registry.lang.dev/index/acme.payments/1.2.4
    targets[2]:
      - triple: aarch64-apple-darwin
        bll: blake3:def456...
      - triple: x86_64-unknown-linux-gnu
        bll: blake3:789abc...
  - name: std.http
    version: 0.5.2
    sbl: blake3:...
    source: registry
    targets[1]:
      - triple: aarch64-apple-darwin
        bll: blake3:...
```

- **`sbl`** — content hash of canonical `.sbl`
- **`bll`** — per-target blob hash in the global store
- **`source`** — registry URL or path provenance

`lang restore` fails if store contents disagree with hashes. Solutions share one lock at the **solution root** when present; otherwise each package keeps its own `Package.lock`.

## Validation rules

- `name` should match `^[a-z][a-z0-9]*(\.[a-z][a-z0-9]*)*$` (dots optional for local apps)
- Every product target name must exist in `targets`
- Path dependencies must point at a directory containing `Package.ll`
- Dependency cycles are rejected at resolve time
- Published libraries must declare a license via `@license` attribute or package metadata field (see registry docs)

## CLI

| Command | Effect |
|---------|--------|
| `lang package dump` | Print resolved package graph (planned) |
| `lang add <id>@range` | Edit `Package.ll` dependencies + update lock |
| `--manifest PATH` / `LANG_MANIFEST` | Alternate `Package.ll` path |

## Environment overrides

| Variable | Effect |
|----------|--------|
| `LANG_MANIFEST` | Path to alternate `Package.ll` |
| `LANG_SOLUTION` | Path to alternate `Solution.ll` |
| `LANG_OFFLINE` | Skip registry fetch |
| `LANG_REGISTRY` | Default registry base URL |
